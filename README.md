# UltraDL 4K — Профессиональная обработка, получение и верификация видеофайлов

**UltraDL 4K** — современный полнофункциональный программный комплекс для работы с видеоматериалами из разрешенных источников, поддерживающий разрешения до **2160p (4K UHD)**, объединение аудио- и видеопотоков через **FFmpeg**, защиту от SSRF-атак и многоуровневую систему проверки на битые кадры и черный экран.

---

## 1. Архитектура и стек технологий

Приложение построено по двухкомпонентной схеме:
1. **Интегрированный Full-Stack Runtime (Google AI Studio / Production Node.js):**
   - **Frontend:** React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Motion.
   - **Backend & Медиа-движок:** Node.js, Express, `child_process` (безопасный вызов утилит `ffmpeg` и `ffprobe`), `multer` для загрузки файлов, встроенная SSRF-защита DNS-уровня.
   - **Сервер:** Единый порт 3000 (`server.ts` монтирует `vite.middlewares` в dev-режиме или отдает production-статику `dist`).

2. **Автономный микросервисный бэкенд (Python 3.12+ FastAPI в каталоге `/backend`):**
   - **Язык & Фреймворк:** Python 3.12, FastAPI, Uvicorn, Pydantic v2.
   - **Обработка видео:** Асинхронный запуск системных процессов `ffmpeg` и `ffprobe`.
   - **Контейнеризация:** Готовый `Dockerfile` (образ `python:3.12-slim-bookworm` с установленным FFmpeg) и `docker-compose.yml`.

## 2. 9-Этапная защита от черного экрана и повреждений (Black Screen Protection)

Система **никогда не объявляет статус «Проверка пройдена» (Passed)**, пока не завершатся все этапы:

1. **Проверка физического файла:** Контроль наличия на диске и размера строго `> 0 байт`.
2. **Анализ сигнатуры контейнера (Magic Bytes):** Чтение первых 128 байт заголовка (проверка ISO Base Media `ftyp` для MP4/MOV, EBML `\x1a\x45\xdf\xa3` для WebM/MKV, `RIFF...AVI `). Расширение файла не считается доказательством.
3. **Глубокое зондирование (ffprobe):** Синтаксический разбор длительности, битрейта, числа потоков, разрешений и кодеков.
4. **Контроль видеопотока:** Ошибка, если файл содержит только аудио или пустой контейнер.
5. **Контроль аудиопотока:** Предупреждение, если звук отсутствует (кроме случаев, когда пользователь явно выбрал видеоряд без звука).
6. **Тестовое декодирование кадров:** Запуск `ffmpeg -v error -stats -i file -t 5 -f null -` для обнаружения битых NAL-блоков, некорректных макроблоков или сбоев декодера.
7. **Анализ черного экрана (Black Screen Detection):** Запуск фильтра `blackdetect=d=0.5:pic_th=0.98:pix_th=0.10` и замер средней яркости `signalstats YAVG`. Ошибка, если проверенное видео состоит из черных/пустых кадров.
8. **Проверка согласованности метаданных:** Проверка соответствия геометрии кадра (ширина × высота) и длительности.
9. **Итоговый вердикт и сертификация:** Четкое разделение состояний:
   - `Проверка пройдена` (зеленый)
   - `Предупреждение: звук отсутствует` (желтый)
   - `Предупреждение: обнаружен фрагмент черного экрана` (желтый)
   - `Ошибка: видео повреждено` (красный)
   - `Ошибка: видеокадры не декодируются` (красный)
   - `Ошибка: видео полностью черное` (красный)

## 3. Политика источников и этичность

- **Разрешенные источники:** Прямые HTTP/HTTPS ссылки на видеофайлы, лицензии Creative Commons (CC-BY, CC0, Blender Open Movie), публичные достояния (Wikimedia Commons), собственные видео пользователя, загружаемые с компьютера.
- **YouTube:** UltraDL 4K **не обходит DRM**, не имитирует авторизацию клиентов и не нарушает Условия обслуживания (ToS) платформы. При вводе ссылки на YouTube приложение честно информирует пользователя и предлагает официальные способы получения (YouTube Premium «Скачать для офлайн-просмотра» или Google Takeout).
- **Честное 4K:** Приложение отображает только физически существующие в источнике разрешения. Искусственное увеличение разрешения (upscaling) не называется 4K.

## 4. Автоматическое тестирование (12 сценариев)

Приложение включает автоматизированный испытательный стенд, генерирующий синтетические ролики через `FFmpeg lavfi`:
1. `test_1_valid_audio` — Корректный MP4 со звуком AAC.
2. `test_2_valid_no_audio` — Корректное видео без звуковой дорожки.
3. `test_3_empty_file` — Пустой файл (0 байт).
4. `test_4_corrupt_container` — Испорченные заголовки Magic Bytes.
5. `test_5_no_video_stream` — Аудиофайл без видеопотока.
6. `test_6_black_screen` — 100% черный видеоряд (`color=c=black`).
7. `test_7_decode_error` — Видео с поврежденным битовым потоком NAL.
8. `test_8_ffmpeg_merge` — Объединение отдельных потоков аудио и видео через FFmpeg.
9. `test_9_size_limit` — Ограничение максимального размера загрузки.
10. `test_10_unreachable_host` — Сетевая обработка несуществующего домена.
11. `test_11_ssrf_blocked` — Блокировка 127.0.0.1, 169.254.169.254 и локальных сетей.
12. `test_12_4k_sample` — Генерация и подтверждение настоящего 3840x2160 UHD 4K.

### Запуск тестов из терминала:
```bash
npm test
# или напрямую:
npx tsx src/server/test_runner.ts
```

Тесты также можно запустить прямо в веб-интерфейсе во вкладке **«Тесты (12)»**.

## 5. Инструкции по локальному запуску

### Вариант А: Интегрированный запуск (Node.js + FFmpeg, порт 3000)
Требуются установленные `Node.js 20+` и `ffmpeg` / `ffprobe`:
```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev

# Проверка сборки
npm run build
```
Приложение откроется по адресу `http://localhost:3000`.

### Вариант Б: Запуск Python FastAPI бэкенда (`/backend`)
Требуются `Python 3.12+` и `ffmpeg`:
```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

## 6. Развертывание в Docker и Google Cloud Run

### Сборка и запуск в Docker:
```bash
cd backend
docker build -t ultradl-4k .
docker run -p 8000:8000 ultradl-4k
```

Или через `docker-compose`:
```bash
docker-compose up --build
```

### Развертывание в Google Cloud Run:
```bash
# 1. Сборка образа в Google Artifact Registry / Container Registry
gcloud builds submit --tag gcr.io/PROJECT_ID/ultradl-4k ./backend

# 2. Развертывание сервиса
gcloud run deploy ultradl-4k \
  --image gcr.io/PROJECT_ID/ultradl-4k \
  --platform managed \
  --region us-central1 \
  --memory 2Gi \
  --cpu 2 \
  --allow-unauthenticated \
  --set-env-vars STORAGE_DIR=/tmp/storage
```

## 7. Реализованные функции и известные ограничения

### Реализовано:
- [x] Полноценный Full-Stack сервер с интеграцией Vite и системного FFmpeg/ffprobe.
- [x] Анализ прямых HTTP/HTTPS медиапотоков и определение разрешений вплоть до 2160p (4K UHD).
- [x] Загрузка пользовательских локальных файлов (drag & drop) и предварительный анализ.
- [x] Слияние изолированных видеорядов и аудиодорожек с приоритетом режима прямого копирования (Stream Copy).
- [x] 9-этапная система верификации (размер, Magic Bytes, ffprobe, кадры, декодер, детектор черного экрана, согласованность).
- [x] SSRF Guard с DNS-резолвингом и валидацией всех звеньев цепочки редиректов.
- [x] Автоматический испытательный стенд на 12 синтетических сценариев.
- [x] Автономный микросервис Python 3.12+ FastAPI с Dockerfile и compose-файлом.
- [x] Адаптивный темный интерфейс (графит/синий/фиолетовый) на русском языке.

### Известные ограничения:
- Приложение не производит взлом DRM (Widevine/FairPlay) и не обходит защиту авторизованных платформ, таких как YouTube, соблюдая правовые стандарты.
- Проверка кадрового декодирования по умолчанию анализирует контрольный сегмент (до 10 секунд) для быстрого отклика; для очень длинных видео (> 2 часов) полный побайтовый анализ всего файла не производится в реальном времени веб-запроса.
